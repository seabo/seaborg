## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The gen-000..gen-002 bootstrap (TASK-69) plateaued after three generations because the training regime was minimal (small network, few generations, self-play from a weak base) - not because NNUE is exhausted. The next lever is a larger/better network, which needs a substantially larger and higher-quality training corpus. Start generating it now, using idle rig time, in parallel with deciding the new architecture.

Approach: run the TASK-69.6 self-play data-generation binary with the current default network (gen-002, the +337-Elo net) as the labeler, writing the TASK-69.7 packed sample format (position + score + WDL). That format is architecture-agnostic - input features are derived from the position at train time - so this corpus is reusable regardless of the future feature set or topology, and will NOT need regenerating when the architecture is chosen.

Why now: the corpus does not depend on the future architecture, only on label quality, and the rig is idle. Generating at a generous budget de-risks the biggest constraint (label quality) ahead of the architecture decision.

Parameters to set deliberately before the run (these drive rig-hours and label quality):
- Per-move search budget (nodes or depth): set HIGHER than the bootstrap's budget. A larger future net can exploit higher-quality labels, and under-budgeting is the one choice that would force regeneration. This is the key decision.
- Target corpus size (positions/games).
- Opening diversification and adjudication settings (reuse TASK-69.7 defaults unless a reason to change).

Purity: maintain the TASK-69 self-play-purity constraint - no external engines, positions, evaluations, or tablebases enter the corpus. Data is generated solely by seaborg self-play labelled by gen-002.

Scope: primarily an execution/campaign task on the rig. Add only the minimal binary flags or scripting needed to (a) select the higher label budget and (b) chain/accumulate runs into one corpus. This task does not choose the new architecture (separate, upcoming) - it only produces the data that architecture will train on.
